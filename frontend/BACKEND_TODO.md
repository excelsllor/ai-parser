# Frontend features waiting for backend

Состояние: основные пробелы закрыты. Ниже — что осталось.

## 1. Удаление сессии / запуска

Готово:
- `DELETE /api/runs/{id}` удаляет запуск, каскадные записи и каталоги файлов;
- активный запуск сначала переводится в `cancelled`;
- audit-запись `run.delete`;
- кнопки в списке сессий и на странице запуска подключены.

## 2. Профиль

Готово:
- `PATCH /api/auth/me` — `display_name`, `department`, `email` (проверка уникальности email);
- `POST /api/auth/password` — смена пароля с проверкой текущего;
- `GET /api/auth/sessions` — активные refresh-сессии;
- `DELETE /api/auth/sessions/{id}` — завершение сессии;
- `POST /api/auth/sessions/revoke-others` — завершение остальных сессий.

Осталось:
- подтверждение email (сейчас адрес сохраняется без верификации);
- 2FA/TOTP;
- список устройств с IP/User-Agent (сейчас только даты создания/истечения);
- нормализация старых refresh-сессий при логине (сейчас копятся до истечения).

## 3. Параметры создания запроса

Готово:
- `interval_hours` (1–168) в multipart создания запуска, `period_start = control_time - interval_hours`;
- `max_items` (1–20) сохраняется в запуске и используется critic;
- `parent_run_id` для версий;
- UI-переключатели 12/24/48 и 3/5/7/10 подключены.

Осталось:
- per-run флаги политик (склейка дублей, prompt injection, без оценок) — сейчас всегда включены;
- UI файлового режима (backend multipart уже принимает файлы);
- выбор модели/prompt version на странице создания (в админке уже есть).

## 4. Результаты запуска

Готово:
- версии строятся по `parent_run_id` из backend, localStorage больше не используется;
- rerun копирует интервал и лимит и выставляет `parent_run_id`;
- проверка лимита событий использует `max_items`.

Осталось:
- отправка письма на произвольный адрес: UI отправляет только на тестовый адрес из конфига, хотя backend принимает `to`;
- полноценный просмотр вложений/скачивание ZIP — нет.

## 5. Админ-панель

Готово:
- `GET /api/admin/metrics?hours=24` — агрегаты запусков и LLM-токенов;
- все страницы админки работают на реальных endpoint'ах.

Осталось:
- `DELETE /api/admin/users/{id}` фактически деактивирует пользователя; нужен hard delete или явный `disable`;
- история healthcheck (`GET /api/admin/health/history`) — сейчас только live-снимок;
- квота/тариф токенов и ненулевой `llm_calls.cost`;
- поля 2FA в админской таблице (подразделение уже отдаётся в `users`).

Статистика источников:
- `last_synced_at`, `last_error`, `items_collected` заполняются коллектором при live-сборе;
- в админке показываются время синхронизации и ошибка.
